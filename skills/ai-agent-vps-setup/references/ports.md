# 端口角色与变更验收

先记录每个端口的主机、监听地址、协议、拥有者、用途和上游。相同数字在不同主机或协议上不是同一个入口；测试用随机端口也不是新增生产业务。端口号本身不决定速度。

## 端口清单

| 所在位置 | 示例 | 用途及暴露边界 |
| --- | --- | --- |
| VPS | TCP 443 | VLESS / REALITY 主业务入口；云规则、主机防火墙和服务监听需一致。 |
| VPS | TCP 22 或实际 SSH 端口 | 管理入口；不公开部署实例的实际管理端口，不为测速改 SSH。 |
| 客户端回环 | TCP 10808 | 现场常见 HTTP/SOCKS 入口示例；先查实际协议与核心拥有者，通常只绑定回环。不是 VPS 防火墙要开放的端口。 |
| 客户端回环 | TCP 10814 | 某些 TUN 配置的辅助/混合入口示例；含义取决于生成配置。不能仅凭端口存在就认定 TUN 或代理恢复。 |
| 客户端回环 | 动态高位端口 | 隔离核心的临时 SOCKS/管理 API 等，运行时分配、验证未占用，结束后关闭。管理 API 按实现加认证，绝不公开监听。 |
| VPS | TCP 5201 | 仅按需要临时运行的 iperf3 测量，限制测试来源并及时移除。 |
| 浏览器测试目标 | 目标指定的 UDP 端口 | STUN 测试使用目标实际端口；这是客户端向外发起测试，不代表应在 VPS 上新增公共 STUN 服务。 |

10808/10814 是已有现场案例中的本机入口，不是通用默认值，也不是该次加固新开的服务器端口。端口必须从当前有效配置与监听者重新确认。通常只需公网 TCP 443 与实际 SSH 入口；本模板 RAW/TCP 不需要为业务新增 UDP 443 入站。

## 确实需要新增或迁移业务端口时

1. 说明原因与预期收益，例如已有端口冲突、路径过滤或限时对照。选定一个空闲、服务商允许的 TCP 端口，不批量放行端口段。
2. 保存相关服务配置、规则及持久客户端模板。新入站必须保留经过验证的认证、TLS/REALITY 和路由限制；新的入站标签不能绕过既有保护。必要时复用或重新生成凭据，由部署边界决定，不能使用公共示例凭据。
3. 在云和主机防火墙仅添加所需端口/协议，校验候选配置，再于约定窗口应用。已有服务重启可能同时影响原端口，保留独立管理及恢复路径。
4. 为候选端口建立隔离客户端，核对实际端点，完成认证、新 HTTPS 请求、出口检查和同条件性能对照。TCP 可连接不等于认证通过，速度改善也不代表断线保护通过。
5. 需要把保护流量切换过去时，同步修改专用出站、DNS 出站、GUI 持久模板及实际生成配置，复核没有直连或未批准节点回退。若保留两个批准端口，故障验收须阻断所有可用路径及已有连接，不能只封旧端口。
6. 候选未改善或出现新错误，恢复本次差异；确认不再引用的旧入口或测试入口后，关闭监听与本次规则。保留多端口需有明确用途，不能把长期扩大暴露面当成加速。

REALITY 的 `target` 是远端伪装目标，其端口独立于本 VPS 监听端口；更换业务入口不能机械改写目标端口。字段语义见 [REALITY 官方配置](https://xtls.github.io/config/transports/reality.html)。

## 本机入口和恢复核验

在本机先读有效配置并查监听者，再做协议握手和全新代理请求。端口由错误进程占用、仍有旧核心残留、GUI 重载生成了不同配置，都不能判恢复成功。记录进程启动身份与实际核心路径；不能仅根据旧 PID 杀进程。

恢复至少确认：生产核心拥有正确监听、TUN 实际选路恢复、代理与 TUN 各自的 HTTPS 成功、受保护域名 DNS 可用、真实应用有新的成功响应。临时入口关闭与正式入口恢复分别记录。详见 [验证与恢复](verification-recovery.md) 和客户端技能的 [故障验收](../../ai-agent-proxy-guard/references/fault-tests.md)。
