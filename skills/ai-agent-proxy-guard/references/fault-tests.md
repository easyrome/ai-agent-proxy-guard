# 故障与恢复验收

用一个真实联网动作回答「应用在故障期间做了什么」。建立请求失败、系统拦截、恢复后再成功是三条独立证据。以下用例不要求访问公共 IP 检测网站；优先使用用户控制的测试目标。

## 演练前

1. 记录受保护身份、二进制版本与签名、PID 和启动时间、有效配置/规则身份、监听者、当前实际节点、IPv4/IPv6 防护和 DNS 路径。私有报告中的原始地址可在本地保存，对外只保留类别。
2. 在保持保护开启的情况下拿到阳性基线：用实际桌面或 CLI 产生可区分的新请求，核对实际出站和对端响应。选一个应能继续直连的非敏感对照；要验证同目标可达，用独立测试身份访问自有目标，避免让受保护应用先裸连作对照。
3. 故障注入需有范围和限时。保存有效配置、GUI 覆写、规则和诊断开关的前像，检查备份可读，数据库做一致性检查。准备独立于代理和当前会话的本地撤销入口、超时自动撤销与人工后备。有远程管理依赖时先验证带外通道。缺少这些条件，就先做只读或隔离演练。

### 让测试在断网后仍可完成

- 每次建立新的运行目录与准备凭据，绑定真实 PID、启动时间、配置及测试脚本哈希；不用上一轮的 `ready`、故障状态或通过记录放行新测试。临近故障开始重新检查基线、采样器寿命和独立恢复进程。
- 看护进程须能在控制器退出后独立撤销故障，事先以临时进程验证。救援截止时间表示**开始恢复**，不是承诺该时刻已联网；恢复时长另测。日期以带时区的 UTC 值存储，用明确的区域无关解析，并测试本机常见区域格式，拒绝未来或过期凭据。
- 远程指令可能因代理断开而延后。故障前准备本地、有限次且有唯一标记的请求动作，明确调度时刻不等于实际发送时刻；同时启动有容量上限、能及时落盘的取证。权限和工具不支持时，采用人工本地动作或隔离演练，不把迟到的恢复期请求算作故障样本。
- Windows 启动入口含中文路径时核对实际代码页和参数传递。可用 ASCII 启动器调用正确引用的 Unicode 脚本路径或编码命令；先走同一入口的只读检查，再执行已获准的故障。编码仅解决参数传递，不改变权限要求或绕过系统批准。

## 逐项运行

| 场景 | 先证明故障成立 | 受保护路径的预期 | 对照 |
| --- | --- | --- | --- |
| 上游 VPS 断开 | 本机监听和 TUN 仍在，逐一证明所有可承接受保护流量的核心及其 TCP/UDP、IPv4/IPv6 上游失联，包括已建立的传输。只拦一个核心、只改一个节点地址会造出假故障。 | 从新请求开始直到故障结束应无未经批准的响应或外发。若要求固定单一出口，自动换到另一个代理也判失败。 | 无关直连仍可用。 |
| 整套代理退出 | GUI、后台服务、核心、TUN 路由、真实本地代理监听均已退出；重连守护未在中途复活。 | 新请求失败或在故障窗口内未完成。应用改用系统默认路由时应被独立边界拦住。 | 物理网络保持可用，排除整机断网造成的假阳性。 |
| 仅停 TUN | TUN 与相关路由确已撤下，原本机代理及其上游能通过新连接处理请求。若 GUI 开关连带重载核心，先换可区分的隔离方案。 | 显式代理可以继续成功，经批准出口取证；只依赖隧道的路径应失败。不允许物理直连。 | 用已知走本机代理的独立请求确认余下路径正常。 |

按目标架构选择适用项。手机切 Wi-Fi/移动网络、休眠唤醒、应用升级、新增网卡和冷启动都可能改变边界；只对实际执行的条件给结论。

## 怎样判断结果

Windows 采样示例：在本地 PowerShell 中先将 `$targetIds` 设为本轮已核验的主进程和网络子进程 PID 数组，`$localProxyPort` 设为实际代理端口，然后在技能目录运行。

```powershell
& ./scripts/observe-windows.ps1 -ProcessId $targetIds -ProxyPort $localProxyPort -Samples 8 -IntervalMs 750
```

输出按进程与采样时间分组。`expected_loopback_port` 只表示标准回环地址和预期端口，监听者及上游身份需要另外验证。`non_loopback` 可包含隧道或内网连接，需要查接口和发送者。`null` 表示无法取得可信值；退出码 2 表示取证不完整。采样过程中新增的子进程要重新识别并加入，不能把旧 PID 的结果外推。

浏览器先证明同 origin、同请求机制在正常网络能得到新响应。页内 `fetch` 若被 CSP 或 CORS 拒绝，要区分未发请求和收到响应但脚本不可读；前后都失败的探针不能证明断流。可改用浏览器允许的顶层导航并排除缓存、Service Worker，保留前后成功及故障错误页；不要关闭 CSP、证书校验或防护策略来凑通过。[CSP connect-src 规范](https://www.w3.org/TR/CSP3/#directive-connect-src)

- 每次使用新的请求标记或只能从服务端获得的新值。对齐故障开始、请求提交、结果出现、恢复开始和恢复后的时间。故障中一直等待、恢复后才看到回复，记「窗口内未完成，服务端完成时刻未知」。没有故障期间的新请求就不能通过该实际应用用例。401/403 加服务端请求标识只能证明传输可达。
- 故障样本须开始和结束都在已确认的稳定故障窗口内；过渡与恢复期单列。事件缓冲丢失时，保留 `raw_request_chain_unverified`，不补造开始/失败时间。唯一请求标记、实际错误文档及其加载事件若能形成有界间接关联，可单列“观察行为通过”，说明时钟和唯一触发条件；这不等于原始逐请求链完整或连续抓包无泄漏。
- **阻断归因**需把实际进程身份、启动时间、动作窗口以及对应 WFP/防火墙规则或隔离边界的丢弃记录串起来。归因要区分 CLI、桌面网络服务和测试探针。无匹配事件，写「阻断归因未验证」。若应用只尝试了失效的回环代理，它可以表现正确而不触发任何公网 Block。
- **路径观察**可结合标有入口/出站的核心日志、受控对端日志、物理接口和隧道的连续抓包。区分「核心到批准节点」和「应用到公网」；共享 DNS 服务与加密应用流量还需额外关联。受控目标、观察窗口、接口与协议的覆盖都要留档。间歇 TCP 快照和 UDP 本地绑定没有对端信息，无法排除采样间隙的短连接和 UDP 外发。
- **反例优先。** 看到本地 ISP 出口出现在本应固定走代理的路径、受保护查询送往未批准解析器、或受保护程序直接通过物理接口联系公网，记失败并暂停该用例。普通应用按原分流直连是正常对照。同一请求若可能涉及先失败后回退，观察整个重试周期；窗口不足则注明。
- 需要主动诱发直连以证明系统规则时，用隔离环境、无业务凭据、经批准的目标地址和可归因的**真实身份**。上游或出口预先设独立兜底，使配置错误也不把用户公网 IP 送到第三方。测试时持续生效的兜底和被测规则要能区分；只有兜底命中时，被测规则仍未验证。

## 恢复与报告

先停止主动直连尝试和待重试的测试请求。若主保护漏放、未生效或只有独立兜底命中，立即暂停相应应用。逐项区分三种资产：切断上游的临时故障规则、用于观测的诊断开关、保障测试不泄露的独立兜底。仅撤销故障注入，保留正式保护及独立兜底，恢复原有核心与配置。

确认端口由预期程序接受**新连接**、实际路由和 DNS 可用。重做直连对照、代理 HTTPS 和适用的浏览器、IPv6 检查。在受保护边界内用另一个新标记复测目标应用。正式保护和批准路径已独立确认后，才移除测试兜底并将诊断开关恢复原值。若仍需兜底才能安全运行，交付时明确记录依赖；撤去兜底前先关闭受影响应用并阻止自动重启。最后核对正式规则、临时规则与进程清单，保留失败记录。恢复脚本退出 0、进程存在或端口处于 LISTEN，均不能代替应用恢复。

可用以下格式交付。证据不足填「未验证」，确无该组件或能力需求填「不适用」并写明原因。

| 项目/场景 | 应用身份与地址族 | 结果 | 可复查的证据和窗口 | 未覆盖范围 |
| --- | --- | --- | --- | --- |
| 分流、DNS、WebRTC、IPv6（逐项） | | | | |
| 上游中断、代理全退、仅停 TUN（逐项） | | | | |
| 系统拦截归因 | | | | |
| 故障撤销及实际恢复 | | | | |

例如，桌面新请求在整套代理退出期间明确失败，快照只见回环重试，恢复后另一个新请求成功；这足以报告该版本在该次故障中的应用行为。没有匹配该进程的丢弃事件或连续出口取证，系统拦截归因和采样空窗仍为未验证。
